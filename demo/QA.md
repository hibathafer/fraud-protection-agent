# أسئلة اللجنة المتوقعة — أجوبة قصيرة وصادقة (T10)

> قاعدة ذهبية: **جاوبيل بصراحة حتى عن الضعف.** سؤال ما تعرفين جوابه:
> "سؤال ممتاز، أثبّته وأجاوبك بعد العرض" — وسجليه.

---

### س1. ليش القرار بقواعد بسيطة واللغة بـ LLM؟ (مقلوب مو أحسن؟)
القرار يجي من قواعد Python شفافة: كل نقطة تُشرح بجملة عربية وتُقرأ بالسجل —
وإذا الغلط نعرف ليش ونصلحه. الـ LLM يعيد صياغة رسالة التوعية بس: **ما يشوف
score ولا يغيّر القرار أبداً** (مثبت بـ `tests/test_llm_safety.py`).
جواب مختصر: **القواعد للحكم لأنها قابلة للتدقيق، والـ LLM للغة لأنه قوي بها.**

### س2. كيف تتعاملون مع الإنذارات الكاذبة؟
أولاً أرقام من الملف المعزول: **FPR = 3.2%** (الهدف ≤5% — تحقق)، وحجوزات
الخاطئة من 23 = اثنين فقط (**91.3% مبررة**). وثانياً تصميم: allow يمشي بلا إزعاج،
warn يشرح ويمنحك تهدئة، وطلب يزيد الثقة يخصم نقاطاً (موثوق −25) فلا ينعاد.
وأي تعديل أثر على الأرقام يعيد الاختبار المعزول (T9) مرة ثانية.

### س3. شكد الدقة بالضبط؟ (ما تتهرّب)
`recall = 44.6%` من الاحتيال، `precision = 34.2%` لأي تنبيه، `macro recall = 47.8%`.
**تحت هدفنا الذاتي (80%) ونقولها بصراحة.** السبب الأساسي موثّق: صياغات ما
طابقت كلمات الكتالوج (كل أمثلة FN بدرجة 20). الأرقام كاملة بـ
`docs/evaluation_report.md` — ما تنعدّل بعد التشغيل المعزول.

### س4. ليش مو Deep Learning أو نموذج لغوي يحكم مباشرة؟
بيانات صغيرة (آلاف الصفوف مو ملايين)، ونحتاج **كل نقطة تُشرح بسطر عربي**
لمستخدم عراقي عادي، ونظام يشتغل بدون نت. نموذج يحكم مباشرة = سوداء ما
تُفسَّر + مخاطر حقن وأرقام مخترعة. لاحقاً ممكن نضيف تعلّماً فوق نفس البنية.

### س5. ليش ما تمنعون التحويل من الأساس بدل ما تعتمدون المستخدم؟
استقلالية المستخدم شرط التحدي وقيمة مقصودة: ما نجمّد حسابات ولا نمنع إجبارياً.
بدل المنع: تحذير شديد + **فترة تهدئة 10 ثوانٍ** + طلب فهم المخاطر + سجل تدقيق
غير قابل للتلاعب بكل تدخل وقرار. الحماية بالضغط النفسية، مو بالسجن.

### س6. شنو يشوفه الـ LLM بالضبط؟ (خصوصية)
الحد الأدنى: قالب التوعية + ≤3 أسباب ثابتة. **لا score، لا سجل معاملات، لا
أرصدة، لا PIN، لا بيانات أحد.** الناتج يمر validators (عربي، ≤70 كلمة، بدون
أرقام/روابط جديدة) وإلا يرجع القالب. كل التفاصيل والأدلة:
`docs/privacy_notes.md`.

### س7. كيف يشتغل بدون إنترنت؟
وضع `COACH_MODE=template` (الافتراضي): قوالب عربية مكتوبة جاهزة + القواعد
كلها محلية. الـ LLM اختياري تمامًا — لو فشل أو تأخر أو المفتاح مو موجود يرجع القالب
تلقائياً بدون أي رسالة خطأ للمستخدم.

### س8. أي موديل؟ وكم يستهلك؟
`gemini-3.6-flash` عبر مكتبة google-genai (الاسم الفعلي موثّق بـ
`docs/DISCLOSURE.md` ويُطبع بـ `python -m src.demo_check`). استدعاء وحيد
لكل رسالة توعية عند الحاجة فقط، والوضع الافتراضي بدون استدعاءات.

### س9. شنو نقاط الضعف الصريحة؟
1. كتالوج **8 أنماط** — صياغات دارجة جديدة تفلت (فشل موثّق بـ FM6).
2. recall 44.6% — نصف الاحتيال يفوت.
3. نص حر بدون مفتاح = "ما فهمنا النص" (مصمّم: ما نخمّن).
4. **56 احتيال** بالمعزول فقط — عينة صغيرة.
كلها موثقة بـ `docs/failure_modes.md` و`docs/evaluation_report.md`.

### س10. كيف تتعاملون مع حقن التعليمات (prompt injection)؟
ثلاث طبقات: (1) نص المستخدم **ما يوصل للـ LLM أبداً** — يوصل فقط القالب
والأسباب الثابتة؛ (2)validators ترفض أرقاماً/روابطًا جديدة؛ (3) حقول الـ JSON
بيضاء — محاولة تهريب `decision`/`score`/`pin` تتسقط قبل الكشف. مثبت بـ
12 اختباراً بـ `tests/test_llm_safety.py`.

### س11. لو بدّلنا الموديل أو أضفنا نمط؟
الموديل: سطر واحد `.env` (`GEMINI_MODEL`) + إعادة تقييم T8.
النمط: ملف JSON بكتالوج `data/scam_catalogue.json` (كلمات + وزن) — **بدون
لمس كود**، وبعدها يمر نفس الاختبارات والتقييم.

### س12. الاختبار النهائي — شلون نثق بالأرقام؟
`python -m src.eval.evaluate --final` شُغّل **مرة وحدة** على `data/test_sealed/`
اللي ما انفتحت قبلها (ممنوع بالتخطيط)، والقواعد كانت **مجمّدة** قبله وبعده.
النتيجة والحدود بـ `docs/evaluation_report.md` وسطر بـ `docs/test_runs.log`.

### س13. شنو البنية التقنية؟
Python + FastAPI + SQLite (قواعد الكشف)، واجهة HTML/CSS/JS **بدون أي
framework وبدون CDN** (تشتغل offline)، محفظة Zain Cash **محاكاة** للعرض،
**294 اختبار** كلها تنجح بدون إنترنت ومفتاح.

### س14. وش يسوي المستخدم النهائي بالضبط؟
يشوف التحذير والأسباب بالعربي، يقرأ رسالة التوعية، **ويقرر**: أكمل أو ألغِ.
قراره يُسجَّل بالسجل مع نتيجة التنفيذ (إيصال أو إلغاء). ما نعلّم قراراته.

### س15. وكيف يجاوب النظام أسئلتها وقت التحذير؟
بمربع حوار صغير داخل نافذة التحذير: تكتب «ليش وقفتوني؟» أو «شنو أسوي؟»
ويرد بـ **50 كلمة كحد أقصى** من حقائق القرار نفسها (أسباب + نمط + نصيحة)،
بشكل جاهز دائماً وبلهجة العراقية. الـ LLM اختياري فوقه. **حد 5 رسائل لكل
معاملة، والحوار ما يغيّر القرار أبداً** — مثبت باختبار صريح.

### س16. شنو وضع التدريب اللي بالصفحة الرئيسية؟
صندوق «وضع تدريب» (Stretch من ملف التحدي): محادثة تعليمية وهمية تلعب فيها
الشخصية دور «موظف الدعم» أو رسائل فاتورة عادية، وتفرّق إنتِ بكل سطر:
«هذا احتيال» أو «أكمل» — وبالنهاية تقييم بسيط (نسبة + حكم + تعليق باللهجة).
**معلن «تدريب» بكل رد، صفر اتصال بقاعدة البيانات، والأحكام من بايثون مو من
النموذج اللغوي** — وما يلمس أي قرار أو بيانات مستخدم.

### س17. كيف يعترض النظام وهو "قبل" تنفيذ التحويل؟
تحويل المحافظ يمشي من `POST /api/wallet/transfer` — الوكيل يقيّمه **قبل** التنفيذ:
`allow` → ينفّذ ويطلع إيصال `ZC...`، و`warn`/`hold` → الطلب **يتعلق** ويظهر تحذير
+ فترة تهدئة 10 ثواني، ثم تختارين: «أكمل» → ينفذ الآن، أو «إلغاء» → ما يصير شي.
الاعتراض مدمج بمسار التحويل نفسه، مو نافذة منفصلة بعده.
الدليل: `src/integrations/wallet_flow.py` + `tests/test_wallet.py`.

### س18. شلون ولّدتوا البيانات؟ وكيف تتأكدون ما فيها شي حقيقي؟
توليد هجين LLM + بايثون ببذورة ثابتة `seed=42` (نفس النتيجة كل مرة): **30 مستخدم
بملفين منفصلين** — التطوير بـ `data/synthetic/` (**20 مستخدم، 3,095 معاملة، 152 احتيال**)
والمعزول بـ `data/test_sealed/` (**10 مستخدمين، 1,561 معاملة، 56 احتيال**) — الصياغات
بـ `prompts/data_gen/`. الفحص بيدك:
`Select-String -Path data\synthetic\*.csv -Pattern "07[0-9]{8}"` → **صفر** (لا هواتف
حقيقية)، وكل الأسماء والعناوين وهمية. المراجعة: `docs/data_review.md`.

### س19. سمعتوا أصحاب المشكلة فعلاً؟ (الدليل الإنساني)
الدليل المطلوب: مقابلات مستخدمين بأسئلة مفتوحة — **3–5 أشخاص** — موثقة بـ
`docs/user_research.md` بنقل حرفي عن تجاربهم مع رسائل الاحتيال والمحافظ، وتحليل
لتكرار الأنماط. ✋ **قبل العرض:** املاي الملف بمقابلاتك — وإذا ما انمّى بعد،
جاوبي بصراحة: "المقابلات مخططة والأسئلة جاهزة بملف مستقل" + اعرضي المصادر
الموثقة للأنماط (روابط التحذيرات الرسمية بذات الملف).
