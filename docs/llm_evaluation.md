# تقييم الـ LLM مقابل القالب (T8)

> تقرير **يدوي** يحتاج مفتاح حقيقي. اختبارات آلية بـ mock موجودة منفصلة
> (`tests/test_llm_safety.py` + `tests/test_llm_eval.py`) وتنجح بدون أي مفتاح.

---

## 1. الطريقة

- **20 سيناريو من dev**: 10 احتيال + 10 بريء، اختيار حاسم بالترتيب
  (`select_scenarios`) — نفس الـ20 كل تشغيل.
- لكل سيناريو نقيّم نفس الـ `assessment` مرتين:
  - **القالب**: نص عربي ثابت جاهز من غير نت (`templates.py`).
  - **الـ LLM**: صياغة `gemini-3.7-flash` لنفس المعنى، تمر بنفس validators.
- الأرقام التلقائية المسجلة: نسبة نجاح الفحص الشكلي، نسبة fallback للقالب،
  متوسط وأقصى latency (ms).
- المقارنة القلمية: **إنسان** يقرأ القالب مقابل صياغة الـ LLM ويقيّم 1-5.

### سؤال التقييم (للملأين)

> **"هل تشبه كلام شخص من العراق أم إشعار بنك مترجم؟"**
> (1 = مترجَم وبارد، 5 = عراقي طبيعي وواضح)

- **الملأ 1**: هبو — عمود `rating_1_5`
- **الملأ 2**: شخص عراقي ثانٍ (غير مشارك بالمشروع) — عمود `rating_1_5_second`

## 2. كيف تشغلينه (خطوة بخطوة)

1. أضيفي بملف `.env` (بالجذر) سطر — بدون فتح `config.py`:
   `COACH_MODE=llm`
   (الوضع الافتراضي `template` يوقف الـ LLM؛ القيم: `template | llm | auto` — شوفي `README.md`.)
2. تأكدي إن `GEMINI_API_KEY` موجود بـ `.env` (ما تفتحينه بـ Git).
3. شغّلي:
   ```bash
   python -m src.eval.llm_eval
   ```
4. تطبع أرقام PASS/FAIL + تكتب `docs/llm_evaluation.csv`
   (يفتح بالعربي سليم بـ Excel — ترميز utf-8-sig).
5. املأوا أنتِ والشخص الثاني عمودي التقييم.
6. سجّلي النتائج بالجدول بالأسفل (بدون تجميل — كما تطلعت فعلاً).

## 3. النتائج

**الحالة الحالية: ⏳ بانتظار التشغيل اليدوي** (يحتاج مفتاح ورصيد Gemini).

| الرقم | القيمة |
|-------|--------|
| نسبة نجاح الفحص الشكلي (ok) | _تُملأ بعد التشغيل_ |
| نسبة fallback للقالب | _تُملأ بعد التشغيل_ |
| متوسط latency (ms) | _تُملأ بعد التشغيل_ |
| أقصى latency (ms) | _تُملأ بعد التشغيل_ |
| متوسط تقييم المُقيِّم1 (1-5) | _بعد التقييم اليدوي_ |
| متوسط تقييم المُقيِّم2 (1-5) | _بعد التقييم اليدوي_ |

> القاعدة: الأرقام تُنسخ **كما تطبعها السكربت** (بالملف والطباعة)، وما
> تُعدّل لاحقاً. لو الـ LLM فشل بكل السيناريوهات، النتيجة تُكتب زي ما هي.

---

## 4. الحدود (صادقة)

- **20 سيناريو** حجم صغير — كافية لتقدير أولي مو لاستنتاج إحصائي.
- التقييم **ذاتي وقارئان** — مو مقياس آلي ولا blinded study.
- **نموذج واحد** (`gemini-3.7-flash`): تغيير النموذج يعني إعادة تقييم.
- **latency** يعتمد على الشبكة وقت التشغيل — رقم لحظي مو ثابت.
- القالب يشتغل دائماً وأونلاين → الـ LLM **تحسين مش شرط تشغيل**.
- الاختبارات الآلية mock بس: صفر استهلاك رصيد، صفر إنترنت بـ pytest.
